# 브라우저 검증 스위트

BrowLab 웹 UI를 **실제 브라우저로 조작해서** 확인하는 스크립트입니다. 파이썬 테스트(`tests/`)가
서버를 검사한다면, 이쪽은 사람이 손으로 하는 일 — 점을 끌고, 문지르고, 두 손가락으로 확대하고,
저장하고 다시 여는 것 — 을 대신합니다. 캔버스 픽셀을 직접 재기 때문에 "지워졌다/결이 남았다"
같은 것도 눈이 아니라 수치로 확인합니다.

```
studio      상담 한 건의 전 과정: 사진 → 자동 배치 → 조정 → 저장 → 갤러리 → 다시 열기 (44항목)
handles     조절점 9개: 간격, 꼬리앞 점, 대칭, 전체 이동, 옛 상담 승격 (7)
heal        잔털 지우기: 붓이 지나간 자리의 제거율과 피부 결 보존, 되돌리기/재생 (9)
pen         아이패드: 펜 획이 손바닥에 끊기지 않는지, 손가락 둘은 여전히 확대되는지 (6)
fullscreen  전체화면이 패널을 남기는지, 브라우저가 제 전체화면을 풀어도 유지되는지 (14)
save        자동 저장과 시안 저장이 서로 다른 일을 하는지, 같은 이름이 번호로 쌓이는지 (7)
zoom        사진만 확대되고 메뉴는 확대되지 않는지 (6)
speed       슬라이더 한 칸·드래그 한 번의 실제 비용과, 캐시가 저장본을 바꾸지 않는지 (7)
```

## 준비

Node 18+ 와 Playwright(브라우저 포함)가 필요합니다.

```bash
npm install -g playwright && npx playwright install chromium
```

서버를 띄우고, **상담이 최소 한 건 있는 상태**로 만듭니다. `studio` 는 사진을 직접 올려 상담을
만들지만, 나머지는 갤러리의 첫 상담을 집어 쓰므로 `studio` 를 먼저 한 번 돌리면 됩니다.

```bash
python -m browlab web --port 8177 --data-dir /tmp/browlab_e2e --no-auth
```

## 실행

```bash
export BROWLAB_PHOTO=/경로/정면사진.jpg      # studio 가 올릴 얼굴 사진 (필수)
node browlab/tools/e2e/studio.mjs           # 먼저 이것부터
for f in handles heal pen fullscreen save zoom speed; do node browlab/tools/e2e/$f.mjs; done
```

환경변수:

| 변수 | 기본값 | 뜻 |
| --- | --- | --- |
| `BROWLAB_URL` | `http://127.0.0.1:8177` | 서버 주소 (`--base-path` 를 쓴다면 그 경로까지) |
| `BROWLAB_PHOTO` | 없음 | `studio` 가 올릴 얼굴 사진 |
| `BROWLAB_OUT` | `e2e-out` | 스크린샷을 남길 폴더 |
| `BROWLAB_CHROME` | Playwright 기본 | 크로미움 실행 파일을 직접 지정할 때 |

각 줄이 `PASS` / `FAIL` 로 나오고, 실패한 줄에는 실제로 잰 수치가 함께 찍힙니다. 마지막 줄의
`JS errors` 가 `none` 이 아니면 페이지에서 예외가 난 것이므로 그것부터 보세요.

## 고칠 때

이 스크립트들은 **수치로 판정**합니다. 임계값을 조정해 통과시키기 전에, 그 수치가 무엇을 재고
있는지 먼저 보세요 — 기준이 틀려서 실패한 적이 여러 번 있었고(예: 붓보다 높은 띠를 한 번에
지우라고 요구했음), 그때는 코드가 아니라 측정을 고치는 게 맞았습니다. 반대로 수치가 실제로
나빠졌다면 임계값을 건드리지 말고 원인을 찾으세요.
